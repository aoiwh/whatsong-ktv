# WhatSong｜我颂——可用性测试脚本

## 一、测试目标

验证三件事：

1. 用户能否顺利完成“粘贴文本批量导入”
2. 用户能否顺利完成“多标签组合筛选”
3. 用户能否顺利完成“创建场次并一键反馈”

同时观察：

- 用户在哪一步卡住
- 用户对标签、反馈的接受度
- 用户是否理解“反馈默认只存本场次、可手动同步全局标签”

## 二、测试对象

- 人数：5-8 人
- 条件：18-30 岁、每月至少 1 次 KTV、会唱 20 首以上
- 与访谈对象可重叠，也可新增
- 最好包含 1-2 位未参与过访谈的新用户

## 三、测试准备

- 准备一段真实歌单文本（20 首左右，含重复、含歌手名、含序号）
- 准备可点击原型（Figma / 墨刀）
- 准备录屏或录音（征得同意）
- 准备记录表（见第五节）
- 准备计时器

## 四、测试任务

### 任务 1：粘贴导入 20 首歌

**任务描述：**

> 假设你有一份会唱的歌单，存在备忘录里。请你把它导入到这个工具里。

**观察点：**

- 是否找到导入入口
- 粘贴后是否理解解析结果
- 遇到重复项如何处理
- 是否知道可以手动修正
- 完成耗时

**成功标准：**

- 成功导入 ≥18 首
- 处理了重复项
- 无严重卡点

### 任务 2：给 5 首歌打标签

**任务描述：**

> 请给刚才导入的 5 首歌打上标签，比如“拿手”“慎点”“适合合唱”。

**观察点：**

- 是否理解标签含义
- 是否觉得标签太多
- 是否知道可以自定义
- 是否愿意继续打更多标签
- 完成耗时

**成功标准：**

- 成功给 5 首歌打标
- 每首歌不超过 4 个标签
- 无严重卡点

### 任务 3：筛选“同事局 + 嗓子一般 + 独唱”

**任务描述：**

> 假设你今晚要和同事去 KTV，嗓子状态一般，想唱几首独唱。请用筛选功能找出合适的歌。

**观察点：**

- 是否找到筛选入口
- 是否理解“且/或”逻辑
- 遇到无结果时如何处理
- 是否知道可以把结果加入场次
- 完成耗时

**成功标准：**

- 成功筛选出 ≥3 首
- 结果符合场景
- 无严重卡点

### 任务 4：创建场次并反馈 3 首

**任务描述：**

> 请创建一个今晚的 KTV 场次，把刚才筛选出的歌加入，然后假设你唱完了 3 首，给它们反馈“稳 / 一般 / 翻车”。

**观察点：**

- 是否理解场次信息哪些必填、哪些可选
- 是否找到反馈按钮
- 是否理解反馈默认只存本场次
- 是否找到“手动同步全局标签”入口
- 完成耗时

**成功标准：**

- 成功创建场次
- 成功反馈 3 首
- 能说出反馈默认只存本场次
- 无严重卡点

### 任务 5：查看统计

**任务描述：**

> 请查看你唱过的歌里，哪首唱得最多。

**观察点：**

- 是否找到统计入口
- 是否理解演唱次数
- 是否误以为系统会自动计算熟练度
- 完成耗时

**成功标准：**

- 找到统计页
- 正确说出演唱次数最多的歌
- 无严重卡点

## 六、测试后访谈问题

1. 哪个步骤最顺手？为什么？
2. 哪个步骤最卡？为什么？
3. 标签数量能接受吗？够用吗？
4. “反馈默认只存本场次、可手动同步全局标签”能理解吗？
5. 愿意在下次 KTV 前用这个工具吗？
6. 什么情况下你会放弃使用？
7. 如果只能保留一个功能，你留哪个？

| 指标 | 目标 |

| 任务 2 完成率 | ≥80% |
| 任务 3 完成率 | ≥80% |
| 任务 4 完成率 | ≥80% |
| 任务 5 完成率 | ≥80% |
| 平均完成耗时 | 每个任务 ≤3 分钟 |
| 整体满意度 | ≥4 分 |

## 八、注意事项

- 不引导用户，不提示答案
- 用户卡住时先观察，超过 1 分钟再给提示
- 记录用户原话，不只记录结果
- 不解释产品设计，让用户自己判断
- 测试后当天整理记录
