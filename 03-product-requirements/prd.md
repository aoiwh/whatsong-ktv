# WhatSong｜我颂——PRD 初稿

## 一、项目背景与目标

### 背景

年轻 KTV 用户的“会唱歌曲”散落在备忘录、微信收藏、聊天记录、音乐 APP 歌单里，长期堆积、无法复用。到了 KTV 临场，用户靠记忆和惯性选歌，缺少场合、嗓子、独唱/合唱、难度等私人筛选维度，容易翻车，且唱完后经验零沉淀。

### 目标

做一款轻量化、私人化的 KTV 选歌与演唱沉淀工具，帮助用户：

1. 低门槛集中零散歌单
2. 临场按私人维度快速筛选
3. 唱完后一键反馈，系统只累计演唱次数，用户可手动同步全局标签

### 非目标

- 不做曲库、播放、歌词、社交、AI 打分
- 不做复杂数据分析
- 不做强制注册登录

## 二、用户画像与使用场景

### 核心用户

- 18-30 岁大学生、年轻职场人
- 每月至少 1 次 KTV
- 会唱 20 首以上
- 有备忘录、收藏或聊天记录记歌习惯

### 核心场景

1. 去 KTV 前 10 分钟：按场合、嗓子、独唱/合唱筛选
2. 包间里临场选歌：按热场、拿手、合唱筛选
3. 唱完后沉淀：一键反馈稳/一般/翻车，系统累计次数，可手动同步全局标签

## 三、产品目标与衡量指标

### 北极星指标

每场 KTV 中通过工具选唱并反馈的曲目数。

### 关键指标

- 激活：首次使用后导入 ≥20 首
- 打标率：导入歌曲中至少打 1 个标签的比例 ≥60%
- 筛选使用率：创建场次前使用过筛选的比例 ≥50%
- 场次记录率：筛选后创建场次的比例 ≥40%
- 反馈率：场次内被反馈的歌曲比例 ≥40%
- 复用率：同一首歌被加入 ≥2 个场次的比例 ≥30%
- 平均选歌时间下降

## 四、功能清单

### 核心功能（P0）

1. 粘贴文本批量导入
2. 曲库列表与搜索
3. 预设标签 + 自定义标签
4. 多标签组合筛选
5. 新建 KTV 场次
6. 场次内选歌快照
7. 一键反馈：稳 / 一般 / 翻车
8. 演唱次数累计

### 暂不做（P2 及以后）

- 场次反馈手动同步到全局标签（P1）
- 最近一次演唱时间（P1）
- 标签分组管理（P1）
- 导入结果批量修正（P1）
- 场次历史列表（P1）
- 分享歌单（P2）
- 多人协作场次（P2）
- 数据导出（P2）

## 五、核心用户流程

> 粘贴文本批量导入 → 解析与修正 → 打标签 → 临场筛选 → 创建场次 → 场次内选歌 → 一键反馈 → 系统累计演唱次数 → 用户可选手动同步全局标签

## 六、页面说明

### 1. 首页 / 我的曲库

- 展示全部歌曲
- 支持搜索、按标签筛选、按演唱次数排序
- 底部入口：导入、筛选、场次

### 2. 批量导入页

- 粘贴文本框
- 解析预览
- 支持手动修正、删除、合并重复
- 确认导入

### 3. 标签管理页

- 预设标签列表
- 自定义标签新增、编辑、删除
- 不强制分组

### 4. 筛选页

- 多标签勾选
- 且/或逻辑切换
- 筛选结果预览
- 一键加入本场次

### 5. 新建场次页

- 场次名称
- 日期
- 场合类型（可选）
- 同行人类型（可选）

### 6. 场次详情页

- 本场次歌曲列表
- 调整顺序
- 一键反馈：稳 / 一般 / 翻车
- 手动同步全局标签（P1）

### 7. 统计页

- 每首歌累计演唱次数
- 最近一次演唱时间（P1）
- 不自动计算熟练度，不自动生成推荐

## 七、异常场景与兜底

| 异常场景 | 兜底方案 |
|---|---|
| 粘贴内容为空 | 提示“请粘贴歌单文本”，不进入解析 |
| 解析不出任何歌名 | 提示“未识别到歌名，可手动添加”，保留原文 |
| 歌名重复 | 自动标记，用户可选择保留一首或全部保留 |
| 歌名含歌手名、符号、序号 | 提供手动修正入口 |
| 筛选无结果 | 提示“没有匹配歌曲，试试减少标签”，支持一键清空 |
| 空标签 | 提示“先给歌曲打标签，筛选才有结果” |
| 无网络 | 已导入数据可本地查看和筛选，场次反馈本地暂存 |
| 误删歌曲 | 提供撤销或回收站 |
| 场次未反馈就退出 | 保留草稿，下次进入可继续 |

## 八、数据埋点与指标

### 关键事件

- import_start / import_success / import_fail
- tag_create / tag_apply
- filter_use / filter_empty
- session_create / session_add_song
- feedback_submit
- tag_sync_manual

### 指标口径

- 导入成功率 = import_success / import_start
- 打标率 = 至少打 1 个标签的歌曲数 / 导入歌曲数
- 筛选使用率 = filter_use 用户数 / 创建场次用户数
- 反馈率 = feedback_submit 歌曲数 / 场次歌曲数

## 九、风险与取舍

### 风险 1：KTV 是低频场景

取舍：不追求高频打开，追求每次去 KTV 都用。

### 风险 2：用户不愿打标签

取舍：预设标签为主，自定义为辅；单首歌建议不超过 4 个；不强制打标。

### 风险 3：用户不愿反馈

取舍：一键“稳/一般/翻车”，默认只存本场次，不强制同步全局标签。

### 风险 4：导入解析失败

取舍：提供手动修正入口，保留原文，不让用户重来。

### 风险 5：功能膨胀

取舍：任何新功能先过 MVP 边界三问，不服务于核心闭环就不做。

## 十、版本规划

### V1（MVP）

粘贴导入、曲库、标签、筛选、场次、一键反馈、演唱次数。

### V1.1

反馈手动同步全局标签、最近一次演唱时间、标签分组、导入批量修正、场次历史。

### V2

分享歌单、多人协作场次、数据导出、深浅色主题。

### 不做

联网搜索、曲库、播放、歌词、社交推荐、AI 打分、复杂报表。
